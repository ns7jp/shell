# 20. PowerShell演習案件概要

## この章の位置づけ

このリポジトリには案件パックが3つあります。この章から始まるのが3つ目です。

| パック | 対象 | 言語 | ドキュメント |
|---|---|---|---|
| 運用パック | 構築済みLinuxサーバーの点検・バックアップ・ログ保守 | Bash + Python | [00](00-project-overview.md)〜[09](09-glossary-cheatsheet.md) |
| 構築パック | LinuxサーバーへのNginx構築と受け入れ試験 | Bash + Python | [11](11-build-project-overview.md)〜[14](14-build-test-plan.md) |
| **PowerShell演習パック** | **WindowsサーバーへのIIS構築と、その後の運用** | **PowerShell 7** | **20〜27（この章から）** |

前の2つはLinuxが対象でした。この章からはWindowsが対象になります。**同じ考え方が言語とOSを越えて通用すること**を、自分の手で確かめるのがこの演習の目的です。

## 架空案件

Linux側の仕組みが動き始めた会社から、続けて次の相談を受けた想定です。

> Linuxサーバーの構築と点検は仕組みができました。ただ、社内にはWindows Serverも数台あります。こちらは担当者が画面（GUI）を手で操作していて、手順も、確認した内容も、記録も人によってばらばらです。新人でも安全にWindowsのWebサーバー（IIS）を構築でき、そのあとの点検・バックアップ・ログ整理まで、Linux側と同じ手順・同じ判定でできるようにしてください。

## 利用者と困りごと

| 利用者 | 困りごと | この案件での解決 |
|---|---|---|
| 新人担当 | 画面のどこを押したか説明できず、再現もできない | 操作をスクリプトにし、`-Execute` を付けない限り何も変更しない |
| Linux担当 | Windowsは別世界に見えて、手伝えない | ログ書式・終了コード・検証順序をBash版と完全にそろえた |
| リーダー | 担当者ごとに手順と品質が違う（属人化） | 設定ファイル1つに「望ましい状態」を書き、誰が実行しても同じ順序で確認する |
| 監査担当 | Windows側だけ証跡の形式が違い、まとめて扱えない | 既存の `scripts/audit_report.py` にそのまま渡して同じJSON証跡にできる |

## スコープ

含むものは、IIS（WindowsのWebサーバー機能）の導入、サンプルページの配置、ファイアウォールでのポート許可、サービスの自動起動設定、構築直後の受け入れ試験、日次点検、世代付きバックアップ、ログの圧縮と整理、追加モジュール不要の自動テスト、証跡化です。

含まないものは、Active Directory（アカウントを一元管理する仕組み）の構築、グループポリシー、ドメイン参加、証明書とHTTPS、負荷分散、クラウド、実際のインターネット公開、Windows Updateの適用制御です。これらは初心者が一人で触ると被害が大きい範囲のため、意図的に外しています。

## なぜPowerShellも学ぶのか

日本の運用・構築の現場では、LinuxとWindowsの両方を扱うことがよくあります。片方しか触れないと、担当できる案件が半分になります。

一方で、**言語を増やすこと自体は目的ではありません**。この演習の主張は次の1点です。

> 「引数を受ける → 値を疑う → 変更する → 確かめる → 終了コードで伝える」という順序は、BashでもPowerShellでも同じである。

同じ順序を2つの言語で書いてあるので、片方を読めばもう片方も読めます。面接では「PowerShellも書けます」ではなく、この対応関係を説明してください。

## 完成条件

1. 初心者がREADMEから、何も壊さずにドライラン（変更せず予定だけ表示すること）を体験できる。

   ```powershell
   pwsh -NoProfile -File scripts\powershell\Install-WebServer.ps1 -ConfigPath config\powershell\websetup.psd1.example
   ```

   設定例は `.psd1.example` のままコピーせずに指定できます。ただしWindows以外では、設定例のパス（`C:\inetpub\wwwroot`）がそのOSの絶対パスではないため終了コード2で拒否されます。パスを自分のホーム配下へ書き換えれば、Windows以外でもドライランを確認できます（[23章](23-powershell-setup.md)）。

2. `-Execute` を付けない限り、1バイトも変更しない。付けた場合も、Windows以外の環境と管理者権限が無い場合は実行前に拒否する。

3. 構築直後に `Test-WebServerBuild.ps1` が、役割・サービス・配布ファイル・HTTP応答・ファイアウォールの5項目を終了コードで判定する。

4. PowerShellが出したログを、**新しい変換スクリプトを作らずに** 既存の `scripts/audit_report.py` でJSON証跡にできる。

5. Windows実機でしか確認できない項目は、成功したことにせず `NOT RUN` と明記する。

## 作業工程

`要件確認 → 設計 → 実装 → 静的検証 → 自動テスト → 検証環境で構築 → 受け入れ試験 → 証跡 → レビュー`

本番作業はこの学習パックの範囲外です。検証環境で成功しても、本番承認を省略できるわけではありません。
