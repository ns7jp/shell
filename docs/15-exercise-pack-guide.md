# 15. Bash演習案件パック（案内）

## この文書は何か

`exercises/` にある演習パックの取扱説明書です。**読むだけの教材ではありません。** 手を動かした結果を採点ツールが機械的に判定し、合否と証跡が残ります。

## 30秒で始める

```bash
bash exercises/labctl.sh init      # 作業場($HOME/bash-lab)を作り、環境を点検します
bash exercises/labctl.sh show E01  # 1問目を表示します
bash exercises/labctl.sh grade E01 # 採点します（0=合格 1=不合格 2=実行エラー）
```

まず覚えるコマンドはこの3つ（`init` / `show` / `grade`）だけです。ほかは必要になったときに `--help` で調べます。

## 覚える量は先に凍結します

初心者が続かなくなる最大の原因は、覚えることが際限なく増えることです。このパックで覚える対象は次の3つだけで、**これ以上増やしません**。

| # | 覚えるもの | 実数 |
|---:|---|---:|
| 1 | 5語スパイン（受ける・疑う・動かす・確かめる・伝える） | 5語 |
| 2 | 骨9要素（スクリプトの骨組み） | 9要素 |
| 3 | 暗記カード（`exercises/cards/cards.tsv`） | 17枚 |

記号は新しく作りません。[ハンズオン](04-hands-on.md)の「まず覚える6記号」をそのまま使います。用語の定義は[用語集](09-glossary-cheatsheet.md)が正典です。採点ツールの内部仕様（判定関数の種類など）は暗記対象ではありません。

## 学習者像と前提

README の「最短5分の体験」を1回実行し、`make test` が終了0になったところまで到達している人を想定します。`cd` `ls` `cat` `mkdir` が打てて、エディタでファイルを保存できれば十分です。

| 知らない前提にしているもの | どこで扱うか |
|---|---|
| 終了コード、`$?` が「直前」を指すこと | E01 |
| 5語がコードのどこにあるか | E02 |
| `source` によるライブラリ読み込み | E03 |
| 引数解析（`while` と `case`） | E04〜E06 |
| 入力検証とフェイルクローズ | E07〜E09 |
| ドライランと冪等性 | E10〜E12 |
| 成果物の確認、落ちるテスト | E13〜E15 |
| 終了コードの出し分け、JSON証跡 | E16〜E18 |

環境は Ubuntu 22.04/24.04 または WSL2、Bash 4.4以上、Python 3.10以上です。**root権限は一度も使いません。ネットワークも使いません。** ShellCheck は任意で、無い場合は静的検査を「未実施（NOT RUN）」と表示します。合格扱いにはしません。

## 到達目標

修了時に、次を **何も見ずに** 実演・説明できる状態を目指します。

1. 5語スパインを順に言い、`scripts/backup.sh` のどの行が5語のどれかを指せる。
2. 骨9要素を白紙から順番どおり書ける。
3. 終了コード 0/1/2 を「無事・注意・無理」と行動（証跡を残す／答案を直す／環境を直す）でセット説明できる。
4. 検証を「ある→形→範囲→場所」の順に書き、危険な入力を終了2で拒否できる。
5. ドライラン既定を実装し、なぜ既定を安全側にするか説明できる。
6. 冪等性を「2回実行して状態が一致すること」と定義し、検証手順を実演できる。
7. 成果物を読み直す型（ある・中身・権限）を実装できる。
8. 自作ログを既存の `audit_report.py` でJSON証跡にできる。
9. **わざと壊した実装で落ちる**テストを書ける。
10. 証跡テンプレート形式で達成記録を出力し、面接で提示できる。

## レベル区分（レベルは7つ、どれも3問）

真ん中の5つ（L1〜L5）だけが5語と1対1で対応します。L0 は準備編、L6 は総合編で、5語とは対応させません。

| レベル | 5語 | 狙い | 問数 | 目安 |
|---|---|---|---:|---:|
| L0 準備編 | — | 道具をつなぎ、採点の読み方を覚える | 3 | 55分 |
| L1 受ける | 受ける | 引数と設定の受け取り方を1種類だけ覚える | 3 | 115分 |
| L2 疑う | 疑う | 検証を自作せず共通関数を呼ぶ習慣をつくる | 3 | 115分 |
| L3 動かす | 動かす | ドライラン既定と冪等性を実装する | 3 | 125分 |
| L4 確かめる | 確かめる | 成果物を読み直し、落ちるテストを書く | 3 | 135分 |
| L5 伝える | 伝える | ログ・終了コード・JSON証跡でつなぐ | 3 | 120分 |
| L6 総合編 | — | 白紙再現・総合デバッグ・引き継ぎ | 3 | 180分 |

L1〜L5 は必ず **写経A → 穴埋めB → 白紙C** の3問構成です。順番も節の構成も採点コマンドも毎回同じなので、内容が変わっても手順を覚え直す必要はありません。

## 採点結果の読み方

```text
ok - 実行して終了コード0            ← 合格した判定
not ok - 標準出力がちょうど1行       ← 不合格の判定
#   見た場所: /home/you/bash-lab/L0/hello.sh
#   期待= 1
#   実測= 2
#   不足= log INFO こんにちは の1行
#   次の一手: bash exercises/labctl.sh hint E03
not run - ShellCheck # NOT RUN（shellcheck が未導入です）  ← 環境が無くて判定しなかったもの
1..4
# pass=3 fail=1 not_run=0
```

読むのは **`期待=` と `実測=` の2行だけ** で足ります。終了コードの意味は次のとおりです。

| コード | 意味 | 次にすること |
|---:|---|---|
| 0 | 合格 | 次の問題へ進み、証跡を残します |
| 1 | 不合格 | **自分の答案** を直します |
| 2 | 実行エラー（IDが違う、作業場が無い、答案が無い等） | **環境か打ち間違い** を直します。まだ採点されていません |

`not run` は「環境が無くて判定していない」という意味で、合格ではありません。実施していない検査を実施済みとして扱わない方針は[検証証跡](08-evidence.md)と同じです。

## ヒントと模範解答の方針

模範解答は `exercises/answers/` にあり、隠していません。**隠す代わりに、開いたことを記録します。**

```bash
bash exercises/labctl.sh hint E09          # 1段階ずつ開きます（H1→H2→H3）
bash exercises/labctl.sh answer E09 --diff # 自分の答案との差分だけを見ます
bash exercises/labctl.sh answer E09        # 全文を見ます（記録が残ります）
```

全文を開いた問題は進捗表に `full` と記録され、3日後の復習で必ず白紙から書き直す対象になります。ごまかしても損をするのは自分だけなので、正直に開いて構いません。

## 復習の回し方

```bash
bash exercises/labctl.sh review   # 今日やることだけを出します（1日20分まで）
bash exercises/labctl.sh card     # 暗記カード17枚
bash exercises/labctl.sh recall   # 何も見ずに入力して照合する自由再生テスト
```

復習は **D1 / D3 / D7 / D21**（合格の翌日・3日後・7日後・21日後）の4回だけです。白紙C問（E06 / E09 / E12 / E15 / E18 / E19）の復習は、既存の答案を採点し直すのではなく、答案を `history/` へ退避してから **白紙で書き直します**。見て思い出せることと、見ずに書けることは別物だからです。

## 進捗と証跡

```bash
bash exercises/labctl.sh list              # 一覧と合否
bash exercises/labctl.sh progress --save   # $HOME/bash-lab/progress/progress.md に進捗表を保存
bash exercises/labctl.sh evidence E09      # 証跡テンプレート形式で1問ぶん出力
```

`evidence` の出力形式は[テスト仕様](05-test-plan.md)の証跡テンプレートと同じです。保存した進捗表は[検証証跡](08-evidence.md)の「演習パック」節に貼ります。**進捗も証跡もリポジトリの中には書きません。** 作業場は `$HOME/bash-lab` です（既存ハンズオンが使う `$HOME/shell-lab` とは別の場所です）。

## 安全について

- 変更は `$HOME/bash-lab` と採点用の使い捨てディレクトリの中だけで起こります。リポジトリには書きません。
- 採点は学習者の答案を複製してから実行します。元のファイルは変更しません。
- `sudo` `apt-get` `systemctl` `ufw` `curl` を実行させる演習はひとつもありません。
- **時間制限**: すべての実行に10秒の制限が付きます。無限ループは打ち切られ、`TIMEOUT` と表示されます。停止要求を無視するスクリプトは、さらに5秒後に強制終了します。
- **出力量の制限**: 1回の実行が書き出せる量に上限（既定20MB）があります。書き出しすぎる答案でディスクを埋めません。
- **後片付け**: 答案が裏で起動したプロセスも、採点のたびに片付けます。

危険なパスを拒否できるかを試す演習（E09 / E12 / E19）では、`/proc` のような**書き込みができないシステムディレクトリ**を渡します。検証をまだ書けていない答案を採点しても、実際のシステムは変更されません。

## このパックが扱わない範囲

`awk` / `sed` の高度な使い方、systemd、実ネットワーク、Ansible、性能試験は扱いません。これらは[サーバー構築ロードマップ](10-server-build-roadmap.md)の未着手項目です。演習パックは、そこへ進むための基礎技能を身につける段階に位置づけています。
