# 02. 基本設計

## 全体構成

```text
利用者
  └─ --config / --execute
       ├─ server_audit.sh ── 読み取り ── OS・/proc・systemd・df
       ├─ backup.sh ──────── 圧縮 ────── データ → バックアップ先
       └─ rotate_app_logs.sh  圧縮/整理 ─ アプリログ → archive
               └─ scripts/lib/common.sh（ログ、検証、終了コード）
```

## 共通処理

`set -E` は関数内のエラーも捕捉しやすくし、`-e` は未処理の失敗で停止、`-u` は未定義変数をエラー、`pipefail` はパイプ途中の失敗を見逃しません。ただし万能ではないため、重要な成果物は作成後にも検査します。

設定読み込み前に、所有者が現在ユーザーまたはrootであり、group/otherの書込ビットがないことを確認します。これは設定ファイルに悪意あるコマンドを混入される危険を減らすためです。

## バックアップ処理フロー

1. 引数と設定ファイルを検査する。
2. 元と先が絶対パスで、危険なパスでないことを確認する。
3. 保存先が元ディレクトリ配下でないことを確認する。
4. ドライランなら実行予定コマンドだけを表示する。
5. 実行時は保存先作成、圧縮、期限切れ削除の順に処理する。
6. `tar -tzf` でアーカイブを読み、最低限の整合性を確認する。

## ログ保守処理フロー

対象を直下の `*.log` に限定し、古いログを `gzip -c` で別ファイルに保存します。圧縮結果が空でないことを確認してから元ログを空にします。削除対象も `*.log.*.gz` に限定します。

## セキュリティ設計

- コマンド引数は引用符と `--` で保護する。
- `eval` を使用しない。
- ユーザー入力をファイル名接頭辞へ使う場合は許可文字だけに限定する。
- `/`、`/etc`、`/var` など重要ディレクトリそのものを拒否する。
- 変更系の標準動作をドライランにする。
- CI権限を `contents: read` に限定する。

## 残るリスク

シンボリックリンク、マウントポイント、同時実行、処理中のファイル変更、ディスク枯渇、巨大ファイル性能は本パックだけでは完全に解決しません。本番化する場合は専用ユーザー、ロック、容量事前確認、スナップショット、監視通知を追加します。
