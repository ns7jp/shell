# 09. 用語集・チートシート

## 重要用語

| 用語 | ひとことで | この案件の例 |
|---|---|---|
| シェル | コマンドを受け取る窓口 | Bash |
| シェルスクリプト | コマンドを順番に記述したファイル | `backup.sh` |
| 標準出力 | 通常結果の出力先 | INFO、OK |
| 標準エラー | エラー用の出力先 | ERROR |
| 終了コード | 成否を数値で伝える値 | 0、1、2 |
| 絶対パス | `/` から始まる完全な場所 | `/var/backups/app` |
| ドライラン | 変更せず予定だけ確認 | `--execute` なし |
| 冪等性 | 繰り返しても意図した状態になる性質 | 保存先の `mkdir -p` |
| 世代管理 | 複数時点のバックアップを残す | 日時付きtar.gz |
| ローテーション | 古いログを圧縮・削除する運用 | `rotate_app_logs.sh` |
| フェイルクローズ | 判断不能なら安全側で停止 | 危険パスを終了2で拒否 |
| 証跡 | 後から確認できる実行記録 | コマンド、日時、ログ |
| JSON | 機械でも読みやすい構造化データ | `audit_report.py` の点検証跡 |
| 原子的置換 | 完成したファイルを一度に差し替える | 途中のJSONを残さない |
| ミドルウェア | OSとアプリの間で動く基盤ソフト | Nginx |
| プロビジョニング | サーバーを望ましい状態に構築すること | `provision_web_server.sh` |
| ファイアウォール | 許可した通信だけ通す仕組み | `ufw allow 80/tcp` |
| 受け入れ試験 | 構築直後に完成条件を確認する試験 | `build_verify.sh` |
| `pipefail` | パイプの途中で失敗しても見逃さない設定 | `set -Eeuo pipefail` |

## 調査コマンド

```bash
pwd                         # 現在地
id                          # 実行ユーザーとグループ
ls -ld PATH                 # 所有者と権限
namei -l PATH               # パス途中の権限
df -hT                      # ファイルシステムの空き
du -sh PATH                 # 対象容量
systemctl status SERVICE    # サービス状態
journalctl -u SERVICE       # サービスログ
tar -tzf ARCHIVE.tar.gz     # 圧縮内容の確認
echo "$?"                   # 直前の終了コード
```

## 5語の暗記法

**受ける・疑う・動かす・確かめる・伝える**

1. 引数と設定を受ける。
2. 値、権限、対象を疑って検証する。
3. ドライラン確認後に処理を動かす。
4. 成果物とサービス状態を確かめる。
5. ログと終了コードで結果を伝える。

## 5語とレベルの対応

[Bash演習案件パック](15-exercise-pack-guide.md)のレベル L1〜L5 は、この5語と1対1で対応します。L0（準備編）と L6（総合編）は5語と対応しません。

| 語 | レベル | そこで書けるようになること |
|---|---|---|
| 受ける | L1 | `--config` / `--execute` / `--help` / 不明引数の4分岐 |
| 疑う | L2 | ある→形→範囲→場所の順で検証し、終了2で拒否する |
| 動かす | L3 | ドライラン既定と冪等な処理 |
| 確かめる | L4 | 成果物の確認と、わざと壊した実装で落ちるテスト |
| 伝える | L5 | 終了コードの出し分けとJSON証跡 |

暗記の材料だけを1枚にしたものが[暗記チートシート](17-memory-cheatsheet.md)です。復習は `bash exercises/labctl.sh review` が出題します。

## 採点の言葉

演習パックの採点画面に出る言葉です。

| 用語 | ひとことで |
|---|---|
| `ok - ` | 1件の判定に合格した |
| `not ok - ` | 1件の判定に不合格だった |
| `not run - ` | 環境が無くて判定していない（合格ではない） |
| `1..N` | その回に行った判定の総数 |
| アサーション | 「こうなっているはず」という1つの合格条件 |
| 正規化 | 日時やパスなど環境で変わる部分を揃えてから比べること |
| 状態ハッシュ | ファイル一覧と中身から作る指紋。冪等性の確認に使う |
| サンドボックス | 採点のたびに作る使い捨てのディレクトリ |
| `NOT RUN` | 未実施。予定や推測を成功実績として扱わない |

## 作業前チェック

- [ ] ホスト名、環境、実行ユーザーは正しいか
- [ ] 対象と除外対象を声に出して確認したか
- [ ] バックアップまたは復旧方法はあるか
- [ ] ドライランの表示は意図どおりか
- [ ] 影響時間と承認者は明確か

## 作業後チェック

- [ ] 終了コードを直後に記録したか
- [ ] 成果物を読み直したか
- [ ] サービスを利用者視点でも確認したか
- [ ] ログに秘密情報が含まれていないか
- [ ] 未実施項目をNOT RUNとして残したか
