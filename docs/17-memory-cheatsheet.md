# 17. 暗記チートシート（1枚）

**覚えるのは、5語スパインと骨9要素と暗記カード17枚だけです。これ以上は増やしません。**

印刷して手元に置いてください。用語の意味は[用語集](09-glossary-cheatsheet.md)、記号は[ハンズオン](04-hands-on.md)の「まず覚える6記号」が正典です。ここには **覚え方と復習の材料だけ** を置いています。

## 1. 5語スパイン

> **受ける・疑う・動かす・確かめる・伝える**

| 語 | 何をするか | レベル | 代表的なコード |
|---|---|---|---|
| 受ける | 引数と設定を受け取る | L1 | `while (($#))` と `case` |
| 疑う | 値・権限・対象を検証する | L2 | `require_absolute_safe_path` |
| 動かす | ドライラン確認後に処理する | L3 | `run_or_show "$execute" ...` |
| 確かめる | 成果物とサービスを確認する | L4 | `[[ -s $archive ]]` / `tar -tzf` |
| 伝える | ログと終了コードで伝える | L5 | `log OK` / `exit "$EXIT_WARNING"` |

レベルは7つ、どれも3問。**真ん中の5つが5語** です。L0 は準備編、L6 は総合編で、5語とは対応しません。

## 2. 骨9要素

「9行」ではなく「9要素」です。実物は40行前後になります。雛形は `exercises/templates/spine.tmpl` です。

| # | 要素 | 5語 |
|---:|---|---|
| 1 | shebang（`#!/usr/bin/env bash`） | — |
| 2 | 安全設定（`set -Eeuo pipefail`） | — |
| 3 | 共通ライブラリ読込（`source`） | — |
| 4 | usage（使い方の表示） | 受ける |
| 5 | 引数解析（`while` と `case`） | 受ける |
| 6 | 入力検証（ある→形→範囲→場所） | 疑う |
| 7 | ドライラン既定の処理（`run_or_show`） | 動かす |
| 8 | 成果物の確認 | 確かめる |
| 9 | ログと終了コード | 伝える |

`set -Eeuo pipefail` は語呂で覚えません。意味は[基本設計](02-design.md)に戻って確認します（`E` は関数の中でも捕捉、`e` は失敗で停止、`u` は未定義変数を拒否、`pipefail` はパイプ途中の失敗を見逃さない）。

## 3. 暗記カード17枚（印刷用）

原本は `exercises/cards/cards.tsv` です。出題は `bash exercises/labctl.sh card` で行います。

### spine デッキ（5枚）

| ID | 表 | 裏 |
|---|---|---|
| S1 | 受ける とは | 引数と設定を受け取る。`--config` / `--execute` / `--help` / 不明引数の4分岐 |
| S2 | 疑う とは | 値・権限・対象を検証する。ある→形→範囲→場所の順 |
| S3 | 動かす とは | ドライランで見せてから処理する。既定は安全側、危険は明示 |
| S4 | 確かめる とは | 作った成果物を読み直す。ある・中身・権限 |
| S5 | 伝える とは | ログと終了コードで結果を伝える。書式が同じなら道具は使い回せる |

### exitcodes デッキ（3枚）

| ID | 表 | 裏 |
|---|---|---|
| X0 | 終了コード 0 | 無事。証跡を保存して次へ進む |
| X1 | 終了コード 1 | 注意。WARN行を読んで自分の答案を直す |
| X2 | 終了コード 2 | 無理。環境か引数を直して再実行する |

### messages デッキ（5枚・エラーからの逆引き）

画面に出るのはメッセージのほうです。関数名を先に覚えるより、この向きのほうが現場で思い出せます。

| ID | 表（画面に出る文言） | 裏（原因の関数と対処） |
|---|---|---|
| M1 | 「重要なシステムディレクトリ」 | `require_absolute_safe_path` が `/etc` などそのものを拒否した |
| M2 | 「空でない絶対パス」 | `require_absolute_safe_path` が相対パスや空文字を拒否した |
| M3 | 「.. は使用できません」 | `require_absolute_safe_path` が親ディレクトリ参照を拒否した |
| M4 | 「1 から 65535 の範囲」 | `require_integer_range` が範囲外の値を拒否した |
| M5 | 「他ユーザーから書き込み可能」 | `load_config` が設定ファイルの権限を拒否した。`chmod 600` で直す |

### order デッキ（4枚・順番もの）

| ID | 表 | 裏 |
|---|---|---|
| T1 | 疑う順は | ある→形→範囲→場所 |
| T2 | 確かめる3点は | ある・中身・権限 |
| T3 | 学習の3段階は | 写す→埋める→書く |
| T4 | バグ3種は | 引用符・終了コード・パイプ |

## 4. 借りる共通関数（覚えるのは名前ではなく「自作しないこと」）

`scripts/lib/common.sh` にあります。**同じものを自分で書かないこと** が要点です。

| 関数 | 何をするか |
|---|---|
| `log レベル メッセージ` | 「日時 [レベル] メッセージ」で1行出す |
| `die メッセージ` | エラーを出して終了2で止める |
| `require_command 名前` | コマンドの存在確認 |
| `require_file パス` | ファイルの存在確認 |
| `load_config パス` | 設定を読み込む。所有者と権限も検査する |
| `require_integer_range 名前 値 最小 最大` | 整数と範囲の検査 |
| `require_absolute_safe_path 名前 値` | 絶対パス・危険パス・`..` の検査 |
| `run_or_show 真偽 コマンド...` | ドライランなら表示、`true` なら実行 |

## 5. 復習カレンダー

復習は **D1 / D3 / D7 / D21** の4回だけです（合格の翌日・3日後・7日後・21日後）。1日20分を上限にします。

```bash
bash exercises/labctl.sh review   # 今日やることだけを出します
bash exercises/labctl.sh card     # 暗記カード（5分）
bash exercises/labctl.sh recall   # 何も見ずに入力する自由再生テスト（週1回）
```

白紙C問（E06 / E09 / E12 / E15 / E18 / E19）の復習は、**答案を退避して白紙から書き直します**。既存の答案を採点し直しても記憶の確認にはなりません。

| | 見れば分かる（認識） | 見ずに言える（再生） |
|---|---|---|
| 確かめ方 | `card` の自己申告 | `recall` の機械照合、白紙C問のPASS |
| 面接で必要なのは | — | こちら |

## 6. つまずき横断表（症状 → 原因 → 対処）

| 症状 | 原因 | 対処 |
|---|---|---|
| `$?` がいつも 0 | 別のコマンドを挟んでから見た | 対象コマンドの **次の行** で見る |
| `unbound variable` で止まる | `set -u` があるのに未定義変数を参照した | `${VAR:-}` で受ける |
| 空白入りパスで壊れる | 変数を引用符で囲っていない | `"$var"` と書く |
| パイプの途中の失敗を見逃す | `set -o pipefail` が無い | `set -Eeuo pipefail` をそのまま写す |
| `readonly variable` エラー | 共通ライブラリを同じシェルで2回読んだ | 読み込むのは1回。子プロセスで実行する |
| 「重要なシステムディレクトリ」 | `/etc` などそのものを指定した | 専用のディレクトリを指定する（M1） |
| 「空でない絶対パス」 | 相対パスを渡した | `/` から始まるパスにする（M2） |
| 「1 から 65535 の範囲」 | ポート番号が範囲外 | 範囲内の値にする（M4） |
| 「他ユーザーから書き込み可能」 | 設定ファイルの権限が緩い | `chmod 600 設定ファイル` （M5） |
| 採点が終了2 | 作業場が無い・答案が無い・IDが違う | `init` / `start` をやり直す。**採点はまだされていない** |
| 採点が `TIMEOUT` | 無限ループか入力待ち | ループの終了条件と `read` を見直す |
| ドライランなのにファイルができる | `run_or_show` を通していない | 変更する処理はすべて `run_or_show` 経由にする |
| 2回目の実行で結果が変わる | 成果物の名前に日時や乱数を入れた | 固定名にし、`mkdir -p` / `install -D` を使う |
| `NOT RUN` と出る | ShellCheck などが未導入 | 入れるか、未実施のまま扱う（合格ではない） |

## 7. 60秒で説明する型（E21 の台本）

次の7語をこの順で使えば、案件の説明が1本につながります。

> **5語** → **0** → **1** → **2** → **ドライラン** → **冪等** → **証跡**

「引数を受けて、値を疑って、ドライランで見せてから動かして、成果物を確かめて、ログと終了コードで伝えます。終了コードは 0 が無事、1 が注意、2 が無理です。既定はドライランにして、危険な操作は明示的に指定させます。同じ手順を2回流しても壊れないことを冪等といい、状態が一致するかで確認します。最後に、実行日時・コマンド・期待値・実結果・終了コードを証跡として残します。」
