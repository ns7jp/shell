# 00. 案件概要

## 架空案件

小規模なWebサービスを運用する会社から、次の相談を受けた想定です。

> 担当者ごとに日次点検の方法が異なり、バックアップとログ整理も手作業です。新人でも安全に実施でき、結果を説明できるシェルスクリプトを作ってください。

## 利用者と困りごと

| 利用者 | 困りごと | この案件での解決 |
|---|---|---|
| 運用担当 | 確認漏れが起きる | 点検項目と判定を統一 |
| 新人担当 | コマンドが怖い | ドライラン、安全な初期値、手順書 |
| リーダー | 結果を追えない | 日時付きログ、終了コード、証跡 |
| 復旧担当 | バックアップが使えるか不明 | 作成直後のアーカイブ整合性確認 |

## スコープ

含むものは、Linux基本情報・リソース・サービスの点検、指定データの圧縮バックアップ、アプリログの圧縮と期限切れ削除、設定例、自動テスト、運用手順です。

含まないものは、OSインストール、クラウド構築、監視製品導入、データベース整合性保証、災害対策サイト、秘密情報管理、本番への自動配布です。

## 完成条件

1. 初心者がREADMEから5分でドライランできる。
2. 変更処理は明示的な `--execute` がない限り動かない。
3. 入力不備、警告、正常を終了コードで判別できる。
4. 正常系と危険パス拒否を自動テストできる。
5. 未実施の実機検証を `NOT RUN` と表示できる。

## 作業工程

`要件確認 → 設計 → 実装 → 静的検証 → テスト → 検証環境で試験 → 証跡 → レビュー → 本番承認`

本番作業はこの学習パックの範囲外です。検証環境で成功しても、本番承認を省略できるわけではありません。
