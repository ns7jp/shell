# 21. PowerShell演習の要件定義

## 機能要件

IDは `W-` （Windows）で始めます。運用パックは `F-`、構築パックは表記なしのため、番号がぶつかりません。

| ID | 要件 | 入力 | 出力・判定 | 実装 |
|---|---|---|---|---|
| W-01 | サーバーの基本情報を収集する | 点検設定 | 日時、ホスト名、OS、PowerShell版 | `Invoke-ServerAudit.ps1` |
| W-02 | CPU・メモリ・ディスクをしきい値で判定する | しきい値 | OKまたはWARN | `Invoke-ServerAudit.ps1` |
| W-03 | 指定サービスの稼働を確認する | サービス名の一覧 | 稼働または停止・確認不能 | `Invoke-ServerAudit.ps1` |
| W-04 | 直近のイベントログのエラー件数を判定する | 時間・件数 | OKまたはWARN | `Invoke-ServerAudit.ps1` |
| W-05 | IISの役割を導入する | 役割名 | 導入済みまたは導入実行 | `Install-WebServer.ps1` |
| W-06 | サンプルページを配置する | 配置先、タイトル | `index.html` | `Install-WebServer.ps1` |
| W-07 | 指定ポートをファイアウォールで許可する | ポート一覧、規則名 | 受信許可規則 | `Install-WebServer.ps1` |
| W-08 | サービスを自動起動に設定して開始する | サービス名 | 自動起動かつ稼働 | `Install-WebServer.ps1` |
| W-09 | 構築の完成条件を客観的に確認する | 構築設定 | 5項目のOK/WARNと終了コード | `Test-WebServerBuild.ps1` |
| W-10 | 指定ディレクトリを世代付きで保存する | 元、先、保存日数、接頭辞 | `.zip` と中身の件数確認 | `New-DataBackup.ps1` |
| W-11 | 古いログを圧縮して元ログを空にする | 対象、日数 | `.zip` と0バイトの元ログ | `Invoke-LogMaintenance.ps1` |
| W-12 | 保存期限を過ぎたファイルを削除する | 保存日数 | ドライラン表示または削除 | `New-DataBackup.ps1` / `Invoke-LogMaintenance.ps1` |
| W-13 | PowerShellのログを既存のJSON証跡へ変換する | PowerShellのログ | 件数・総合判定・明細を持つJSON | 既存の `scripts/audit_report.py` |

W-13だけは新しく作りません。**ログの書式をBash版と1文字も違わない形にそろえたため、既存のPythonスクリプトをそのまま再利用できます。** これは「作らなかったこと」が成果である珍しい例です。

## 非機能要件

- PowerShell 7.0以上を前提とする（全スクリプト冒頭に `#requires -Version 7.0` を書き、古い環境では実行前に止まる）。
- Windows Server 2019/2022、Windows 10/11を主対象とする。LinuxのPowerShell 7でも、確認できない項目を警告として明示しながら動く。
- 追加モジュールを一切必要としない（Pester等をインストールしなくても自動テストが動く）。
- 設定値と処理を分離し、秘密情報は設定例にも含めない。
- 管理者権限を前提にしない。必要な処理は事前に権限を確認し、無ければ実行前に止める。
- 空白を含むパス（`C:\Program Files\...`）を壊さずに扱う。
- 重要なシステムディレクトリそのものや `..` を拒否する。
- エラー時に中途半端な成功を報告しない。

## 終了コード

Bash版パックと同じ意味です。この統一自体が要件です。

| コード | 定数名 | 意味 | 運用者の行動 |
|---:|---|---|---|
| 0 | `$OpsExitOk` | 正常 | 証跡を保存して終了 |
| 1 | `$OpsExitWarning` | 警告あり（確認できなかった項目を含む） | WARN行を確認し、手順書で切り分け |
| 2 | `$OpsExitError` | 実行エラー（安全側で停止） | 入力、権限、実行環境を修正して再実行 |

PowerShellでは直前のコマンドの終了コードを `$LASTEXITCODE` で確認します。Bashの `$?` にあたります。

```powershell
pwsh -NoProfile -File scripts/powershell/Invoke-ServerAudit.ps1 -ConfigPath C:\ops\audit.psd1
Write-Output "終了コード=$LASTEXITCODE"
```

## 前提と制約

- CPU使用率は、Windowsでは `Win32_Processor` の `LoadPercentage` の平均です。瞬間値であり、長時間の平均ではありません。
- Linux上で実行した場合のCPU使用率は「1分load average ÷ 論理CPU数」で、Bash版と同じ簡易指標です。値の意味がWindowsとは異なります。
- ファイルバックアップは、実行中データベースのトランザクション整合性を保証しません。
- ログの圧縮は、アプリがファイルを開いたままの場合に失敗することがあります。事前検証が必要です。
- ファイアウォール規則は「受信を許可する」だけで、不要な通信を塞ぐ設計（既定拒否）までは扱いません。
- 役割の導入は、環境によって再起動を必要とする場合があります。この演習では `-NoRestart` を指定し、再起動は人が判断します。

## この演習で「やらないこと」と、その理由

未経験者が一人で触ると被害が大きい、または学習効果に対して危険が見合わない範囲です。

| やらないこと | 理由 |
|---|---|
| Active Directory・ドメイン参加 | 1台の設定ミスが組織全体の認証に波及するため |
| グループポリシー（GPO） | 影響範囲が見えにくく、元に戻す手順が初心者には難しいため |
| ファイアウォールの無効化 | 「動かないから切る」という最悪の癖がつくため。許可規則を足す方向だけを扱う |
| 実行ポリシーの恒久的な緩和 | 端末全体の安全性を下げるため。必要な場面だけ範囲を限定して使う |
| リモート管理（PSRemoting）の有効化 | 認証と暗号化の設計が必要で、この演習の範囲を超えるため |

## 受入条件

各要件は[25. テスト仕様](25-powershell-test-plan.md)のテストID（`PS-` 番号）に対応します。要件とテストを結び付けることをトレーサビリティと呼びます。Windows実機でしか確認できない項目は、テスト仕様側で `NOT RUN` として管理します。
