# 16. 演習パックの採点設計

## この文書は何か

`exercises/` の演習を機械採点する仕組みの設計書です。演習パックの技術的な中身はここに集約しています。採用担当者や現場のレビュアーが「この人はテストを設計できるか」を見る場所でもあります。

## なぜ採点ツールを作るのか

教材だけを置くと、学習者は「できたつもり」と「できる」を自分で区別できません。そこで **合否の判定を人の感想から切り離し、観測できる事実だけで下す** ことにしました。判定の材料は次の4つに限ります。

1. 終了コード
2. レベル語（`OK` / `WARN`）の並び
3. 仕様で明示した出力キー
4. 成果物の状態（有無・中身・権限・状態指紋）

日本語の言い回しは判定材料にしません。正しく書いたのに落ちる事故（誤判定）を防ぐためです。

## 全体構成

```text
exercises/labctl.sh              学習者が打つ唯一のコマンド
  └─ exercises/checks/EXX.check.sh   1問1本の採点スクリプト（子プロセスで起動）
       ├─ exercises/lib/lab_common.sh   scripts/lib/common.sh を読み込む唯一の窓口
       │                                サンドボックス・実行・正規化・状態指紋
       └─ exercises/lib/assert.sh       判定プリミティブ6種と合否の表示
exercises/exercises.tsv          21問の唯一の一覧表（IDと作業ファイルの対応）
exercises/answers/               模範解答（合格するはずのもの）
exercises/answers/wrong/         誤答例（不合格になるはずのもの）
exercises/templates/             写経・穴埋めの雛形
exercises/fixtures/              採点用の教材
exercises/tests/test_labctl.sh   採点ツール自身のテスト
```

## 設計上の判断（4点）

### 1. 共通ライブラリの多重読み込みを構造で防ぐ

既存 `scripts/lib/common.sh` は `readonly EXIT_OK=0 ...` を持つため、同じシェルで2回読み込むと `readonly variable` のエラーで終了1になります。これは採点の不合格（終了1）と見分けがつかず、原因不明の誤判定になります。

対策として、次の3つを規律にしました。**既存の `common.sh` は1行も変更していません。**

1. `common.sh` を `source` してよいのは `exercises/lib/lab_common.sh` だけです。
2. `lab_common.sh` の先頭に読み込み済みガード（`LAB_COMMON_LOADED`）を置きます。
3. `labctl.sh` は採点スクリプトを必ず `bash` の **子プロセス** として起動し、同じシェルへ読み込みません。

### 2. 使い捨てサンドボックスで隔離する

採点のたびに `mktemp -d -t labctl.XXXXXXXX` を作り、その中だけで学習者のコードを動かします。

| 対策 | 内容 |
|---|---|
| 複製して実行 | 学習者の答案はサンドボックスへコピーしてから実行します。元のファイルは読むだけです |
| `HOME` の差し替え | 実行中の `HOME` はサンドボックスです。誤って自分のホームを壊せません |
| 時間制限 | すべての実行に `timeout` を被せます。無限ループは `TIMEOUT` として不合格になります |
| ロケールと時刻の固定 | `LC_ALL=C` `TZ=UTC` を強制し、環境差による揺れを消します |
| 削除の条件確認 | 削除するのは自分が作った `labctl.*` を確認できたときだけです。条件を満たさなければ削除せず停止します（フェイルクローズ） |
| リポジトリを汚さない | 書き込むのは `$HOME/bash-lab` とサンドボックスだけです |

`PATH` は最小構成にしません。最小化すると `cp` や `install` の欠落で誤判定が起きるためです。偽コマンドが必要な演習（E13）だけ、通常の `PATH` の **先頭に** 専用ディレクトリを足します。この仕掛けは問題文の第8節で開示しています。

### 3. 比較の前に必ず正規化する

実行時刻・作業ディレクトリ・ホスト名・改行コードは環境ごとに違います。比較前に `lab_normalize` を通し、次のように置き換えます。

| 対象 | 置換後 |
|---|---|
| `2026-09-03T07:00:00+0000` 形式の日時 | `<TS>` |
| サンドボックスの絶対パス | `<LAB>` |
| 作業場の絶対パス | `<HOME>` |
| ホスト名 | `<HOST>` |
| 行末の `\r`（CRLF） | 除去 |

日時は値ではなく **形** だけを見ます。WSL2 で CRLF が混入しても落ちません。

### 4. 判定は6種類に絞る

| # | 関数 | 判定内容 |
|---:|---|---|
| 1 | `assert_status` | 終了コードの一致（`TIMEOUT` も区別して表示） |
| 2 | `assert_contains` / `assert_not_contains` | 出力の部分一致 |
| 3 | `assert_file` | 有無・空でないこと・権限・状態指紋 |
| 4 | `assert_static` | `bash -n` と、必要な書き方・禁止した書き方 |
| 5 | `assert_lines` | 正規化した出力を期待値と `diff` |
| 6 | `assert_ref_status` | 同じ入力で模範解答と終了コードを比較 |

補助として `assert_shellcheck`（未導入なら未実施）、`assert_equal`、`lab_skip`、`lab_finish` があります。この内訳は採点ツールの内部仕様であり、**学習者の暗記対象ではありません**。

## 不合格表示の仕様

不合格の1件につき、必ず次の5項目を出します。原因の推測を学習者にさせないためです。

```text
not ok - ケース名
#   見た場所: 実際に見に行ったパス
#   期待= ...
#   実測= ...
#   不足= 何が足りないか（具体名）
#   次の一手: bash exercises/labctl.sh hint E09
```

出力形式は既存 `tests/run_tests.sh` と同じ `ok - ` / `not ok - ` / `1..N` に揃えました。集計行は共通ライブラリの `log` を使うため、書式が既存スクリプトと同一になり、採点ログをそのまま `scripts/audit_report.py` へ通せます。

## 終了コード

新しい終了コードは作らず、既存の `EXIT_OK` / `EXIT_WARNING` / `EXIT_ERROR` をそのまま使います。

| コード | 意味 | 学習者の行動 |
|---:|---|---|
| 0 | 合格 | 次へ進む |
| 1 | 不合格 | 自分の答案を直す |
| 2 | 実行エラー（ID不明・作業場なし・答案なし・引数不正） | 環境か引数を直す。採点はまだ行われていない |

環境不足で終了2にするのは `python3` の欠如と Bash 4.4未満だけです。ShellCheck が無い場合は警告を出して続行し、その検査を `NOT RUN` と表示します。**実施していない検査を合格とは表示しません。**

## 採点ツール自身のテスト（最重要）

この種の仕組みで最も起きやすい欠陥は「**採点器が常に合格を返す**」ことです。教材が増えるほど気づきにくくなります。そこで `labctl selfcheck` が全問について次の2つを毎回確かめます。

| 検証 | 期待 | 何を防ぐか |
|---|---|---|
| 模範解答を答案として置いて採点 | 終了0 | 到達不可能な設問（誰も解けない問題） |
| 誤答例を答案として置いて採点 | 終了1 | **常に合格を返す無効な採点** |

加えて `exercises/tests/test_labctl.sh` が、異常系（不明なID・作業場なし・答案なし）で終了2になること、雛形と誤答例に `.sh` が存在しないこと、演習が21問あることを確認します。

```bash
make lab-selfcheck   # 上の2つをまとめて実行します
```

## 拡張子の規約（CIを壊さないための構造的な工夫）

演習パックには「意図的に壊した教材」が必要です。しかしそれを `.sh` で置くと、既存の `make syntax`（`find ... -name '*.sh'`）と `make lint`（`shellcheck` のグロブ）が拾って CI が確実に赤くなります。そこで拡張子で分離しました。

| 置き場所 | 拡張子 | 理由 |
|---|---|---|
| `exercises/templates/` | `.tmpl` | 穴埋め（`__1__` など）は構文として不正なため |
| `exercises/answers/wrong/` | `.wrong` | 意図的に誤った実装のため |
| `exercises/fixtures/broken/` | `.sh.broken` | 意図的に壊した教材のため |
| `exercises/checks/` `exercises/answers/` | `.sh` | 正しい実装なので、むしろ検査対象に入れます |

`SC1090` / `SC1091`（`source` 先を追えない）は道具側の制限で学習者の誤りではないため、`make lab-lint` と学習者向けの静的検査の両方で除外しています。

## CIへの組み込み

既存の `shell-quality` ジョブは1行も変更していません。演習パックの不具合が本体パックの CI を赤くしないよう、独立したジョブに分けています。

```yaml
  exercise-pack:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: Install ShellCheck
        run: |
          sudo apt-get update
          sudo apt-get install -y shellcheck
      - name: Lint exercise pack
        run: make lab-lint
      - name: Self-check the grader
        run: make lab-selfcheck
```

ShellCheck の導入を `lab-selfcheck` より前に置いているのは、静的検査が CI でも恒久的に `NOT RUN` になる事故を防ぐためです。`make check` の定義は変更していないため、README の看板コマンドの実行時間と失敗要因は増えていません。

## 残っているリスク

| リスク | 現状の対策 | 残る限界 |
|---|---|---|
| 既存 `scripts/backup.sh` の行が動くと E02 が壊れる | 前後2行の幅を認め、`selfcheck` が CI で毎回検出する | 行が大きく動いたら模範解答の更新が必要 |
| 既存 `common.sh` のメッセージ変更 | 実測した文言だけを、必要な箇所だけで検査 | メッセージを変えたら該当演習の更新が必要 |
| ShellCheck 未導入の環境 | `NOT RUN` と明示し、合格扱いにしない | 手元で合格しても CI で落ちる場合がある |
| 学習者が想定外の書き方で正解する | 比較対象を終了コードと状態に限定 | すべての正解パターンを網羅はできない |
| root で実行した場合 | `doctor` が警告。root で成立しない検査は採用しない | 権限まわりの体験は一般ユーザーでないと得られない |
