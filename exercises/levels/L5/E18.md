# E18 白紙で証跡1式（白紙C）

| レベル | 5語 | 段階 | 目安 |
|---|---|---|---|
| L5 伝える | 伝える | C（白紙） | 45分 |

## 1. 一行目標

この問題で新しく覚えることは1個だけです。**判定は、終了コードから導きます。**

## 2. 3行解説

- 面接でも現場でも、示せるのは記録だけです。記録の形は `docs/05-test-plan.md` にあります。
- 9項目を、テンプレートと同じ順で上から出します。読む側が同じ順を期待しています。
- 判定は `--status` で受けた終了コードから決めます。`0` なら `PASS`、それ以外は `FAIL` です。

## 3. スパイン位置

**伝える**（骨9要素の9番目「ログと終了コード」を、人が読む証跡の形にします）

## 4. 前提

- 前に合格しておく演習: `E16` `E17`
- 使うカード: `S5` `X0`

## 5. 作業場

```bash
source "$HOME/bash-lab/labenv.sh"
bash exercises/labctl.sh start E18
# 編集するファイル: $HOME/bash-lab/L5/evidence.sh
```

雛形は白紙です。骨9要素を思い出しながら、自分で書きます。

## 6. 手順

1. `sed -n '41,56p' docs/05-test-plan.md` で証跡テンプレートを開き、9項目を数えます。
2. `--status N` を受け取り、`N` が `0` なら `PASS`、それ以外なら `FAIL` を変数に入れます。
3. 9項目を、テンプレートと同じ順で標準出力へ出します。

```bash
bash "$HOME/bash-lab/L5/evidence.sh" --status 0
bash "$HOME/bash-lab/L5/evidence.sh" --status 1
```

## 7. 完了条件

9項目のラベルがテンプレートと同じ順で現れ、判定が終了コードで切り替わることです。

| # | ラベル（行頭） | 中身の例 |
|---:|---|---|
| 1 | `テストID` | `E18` |
| 2 | `日時・タイムゾーン` | `timestamp` の値 |
| 3 | `実行者` | `id -un` の値 |
| 4 | `環境(OS/Bash/commit)` | `uname -sr` と `$BASH_VERSION` |
| 5 | `実行コマンド` | 実際に打ったコマンド |
| 6 | `期待結果` | 終了コード0 |
| 7 | `実結果` | 受け取った終了コード |
| 8 | `終了コード` | `--status` の値 |
| 9 | `判定(PASS/FAIL/NOT RUN)` | `--status 0` なら `PASS`、`--status 1` なら `FAIL` |

## 8. 採点方法

採点器は次のことをします。隠しません。

- 答案をサンドボックスへ複製し、そこで実行します。元のファイルは変更しません。
- `--status 0` で実行し、終了コードが `0` かを見ます。
- 9つのラベルそれぞれについて、**行頭に現れる最初の行番号** を探し、上から昇順かを1件ずつ判定します。ラベルより右（コロンから右）の本文は一切比べません。
- 判定行は、最初のコロンから右だけを取り出して見ます。ラベル自体に `PASS` と `FAIL` の両方が含まれるためです（ケース名 `HARDCODED_VERDICT`）。
- `--status 0` の判定に `PASS` があり `FAIL` が無いこと、`--status 1` の判定に `FAIL` があり `PASS` が無いことを見ます。判定を固定文字列で書いた答案はここで落ちます。

## 11. よくある誤り

| 症状 | 原因 | 対処 |
|---|---|---|
| `HARDCODED_VERDICT` で落ちる | 判定を `PASS` 固定で書いた | 終了コードから判定を導きます。矛盾する証跡は信用されません |
| ラベルの順が違うと言われる | 覚えやすい順に並べ替えた | テンプレートの順を守ります。読む側が同じ順を期待しています |
| 項目が8つしかない | 「日時・タイムゾーン」を1項目と数え忘れた | `docs/05-test-plan.md` を開いて9項目を数えます |
