# E17 ログをJSON証跡にする（穴埋めB）

| レベル | 5語 | 段階 | 目安 |
|---|---|---|---|
| L5 伝える | 伝える | B（穴埋め） | 45分 |

## 1. 一行目標

この問題で新しく覚えることは1個だけです。**`--output` を付けると、ログがファイルにも残ります。**

## 2. 3行解説

- 人が読む報告と、機械が読む証跡は両方いります。もとは同じ1本のログです。
- ログの書式を `log` 関数のままにしておけば、`scripts/audit_report.py` がそのまま読んでJSONにできます。
- JSON の `result` と `audit_report.py` の終了コードは、ログの `[WARN]` の数から機械が決めます。

## 3. スパイン位置

**伝える**（人が読むログと、機械が読む証跡を、同じ書式でそろえます）

## 4. 前提

- 前に合格しておく演習: `E16`
- 使うカード: `S5`

## 5. 作業場

```bash
source "$HOME/bash-lab/labenv.sh"
bash exercises/labctl.sh start E17
# 編集するファイル: $HOME/bash-lab/L5/audit_run.sh
```

埋めるのは `__1__` の1か所だけです。ほかの行は変えません。
このスクリプトは終了コードを出し分けません（それは `E16` で書きました）。

## 6. 手順

1. `sed -n '31,35p' scripts/server_audit.sh` で見本を表示します（そちらは `tee -a` ですが、ここでは `tee` を使います）。
2. `audit_run.sh` の `__1__` を、その1行に置き換えます。この1行は覚えなくてかまいません。
3. 下のコマンドを上から順に実行します。**1行目の `rm -f` を必ず先に実行します。**

```bash
mkdir -p "$HOME/bash-lab/L5/site"
printf 'a\n' >"$HOME/bash-lab/L5/site/a.txt"
printf '%s\n' 'TARGET_DIR="$HOME/bash-lab/L5/site"' \
  "CHECK_FILES='a.txt missing1.txt missing2.txt'" >"$HOME/bash-lab/L5/audit.conf"
chmod 600 "$HOME/bash-lab/L5/audit.conf"

rm -f "$HOME/bash-lab/L5/audit.log"
bash "$HOME/bash-lab/L5/audit_run.sh" --config "$HOME/bash-lab/L5/audit.conf" \
  --output "$HOME/bash-lab/L5/audit.log"
python3 scripts/audit_report.py --input "$HOME/bash-lab/L5/audit.log" \
  --output "$HOME/bash-lab/L5/audit.json"; echo "$?"
```

## 7. 完了条件

`--output` でログがファイルに残り、そのログから作ったJSONが次のとおりになることです。

| 見る場所 | 期待 |
|---|---|
| JSON の `result` | `WARN` |
| JSON の `counts.WARN` | `2` |
| JSON の `entries` の数 | ログの空行を除いた行数と同じ |
| `audit_report.py` の終了コード | `1`（`WARN` があるためです） |

## 8. 採点方法

採点器は次のことをします。隠しません。

- 答案をサンドボックスへ複製し、そこで実行します。元のファイルは変更しません。
- 採点のたびに、`a.txt` だけがある点検対象ディレクトリと、`CHECK_FILES='a.txt missing1.txt missing2.txt'` の設定ファイルを **その場で作ります**。`[WARN]` はちょうど2行になります。
- 本文を `grep -E` で静的に見ます。`tee` の文字列があること、穴の目印 `__1__` が残っていないことの2点です。
- **実行の前に、必ずログファイルを `rm -f` で消します。** 過去のログが混ざる事故を仕組みで防ぐためです。
- `tee` は別プロセスなので、ログの大きさが変わらなくなるまで最大5秒だけ待ってから読みます。
- そのログを `python3 scripts/audit_report.py` に通し、終了コードと、できたJSONの `result` / `counts.WARN` / `entries` の数を1件ずつ判定します。
- `audit_report.py` が終了2になったときは、その標準エラー出力をそのまま画面に出します。

- **コメント以外の行に** 埋め残し（`__1__`）が無いことを確認します。雛形の案内コメントは、消しても残しても構いません。

## 11. よくある誤り

| 症状 | 原因 | 対処 |
|---|---|---|
| `counts.WARN` が合わない | `tee -a` を使い、過去の実行ログが混ざった | ログは1実行1ファイルにします。実行前に `rm -f` します |
| `audit_report.py` が終了2になる | `log` を通らない行が混ざった（`printf` の見出しや `[DRY-RUN]` は日時と `[LEVEL]` を持ちません） | 証跡にするログは、すべて `log` 関数経由の行だけにします |
| `--output` に相対パスを渡すと拒否される | `require_absolute_safe_path` が絶対パスを要求する | 絶対パスで指定します |
